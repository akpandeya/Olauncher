Today weather motion — mock

Design mock for #735: animated effects for the Today page weather card's flat looks, plus lightning. Lightning is forecast-gated, not per-look: a flash and bolt show on a rain or storm look only when lightning is actually predicted — the gate is Open-Meteo lightning_potential (J/kg), reading 0 when there is none — independent of the WMO code. Each frame is the same card with one look; the effect layer sits behind the icon and temperature, as in the app, and the motion is CSS keyframes standing in for the app's WeatherSkyPainter / WeatherEffectView. Example data. The light and dark rows show every look at the mock's fixed wind; the real-data rows drive the same looks from measured data — wind_direction_10m sets the drift's direction, wind_speed_10m its speed, snowfall, cloud_cover, visibility and precipitation the intensity, and lightning_potential the flash. Light and heavy rain add no new look (their streaks now tilt and densify with the same inputs), so they appear only in the lightning row.

Light theme

The page follows the OS setting; these frames are the light variants. Storm and night keep a dark sky in light theme too, exactly as the app's per-look readability table does.

Wind direction & intensity (real data)

The same looks, driven by #735's data plan. wind_direction_10m is meteorological — the direction the wind comes FROM — and the drift follows θ_to = θ_from + 180°, projected to the screen as ux = -sin θ_from, uy = -cos θ_from: a west wind (270°) drifts rightward, an east wind (90°) leftward. wind_speed_10m sets the drift and fall speeds, wind_gusts_10m the gust strength, and snowfall, cloud_cover, visibility and precipitation the intensity. With no script, every frame below hand-sets the keyframes to the labelled values; the badge in the card's corner names the measured inputs, its arrow pointing where the wind blows. Frames pin the light theme — each look's dark variant is unchanged in the row above. Light and heavy rain add no new look: their streaks tilt and densify with these same inputs, which the storm pair shows for the tilt.

Lightning (real data)

#735's newest decision: lightning is forecast-gated, not per-look. The gate is Open-Meteo lightning_potential (J/kg) — it reads 0 when no lightning is predicted — and it is independent of the WMO weather code: above a small threshold, the flash glow and bolt appear on a rain or a storm look alike; below it, the look shows its rain and no flash. The bolt glyph inside the icon is the weather-code icon and stays; only the flash effect is gated. The frames pin the light theme; the first two are the same storm, differing only by the gate, so the A/B is exact.

Self-contained · tokens mirrored from today-weather.html (card sky, ink, halo, rain and icon tokens — the light/heavy rain looks included, as in that page; those mirror values/colors.xml and values-night/colors.xml; page tokens mirror german-surfaces-mock.html) · system fonts, no remote assets, no script — the motion is CSS keyframes standing in for the app's WeatherSkyPainter, WeatherEffectView and WeatherRainView · the wind direction & intensity row hand-sets those keyframes to the measured values of #735's data plan (wind_direction_10m, wind_speed_10m, wind_gusts_10m, precipitation, snowfall, cloud_cover, visibility), standing in for the app's paramsFor(forecast) join · the lightning row gates the flash and bolt on measured lightning_potential (0 = none predicted), independent of the WMO code.
