## Problem

What are we trying to solve, and for whom. Two to four sentences, plain language.
No history, no alternatives — just the problem.

## Design

How it works today's-design intends to work. Use the smallest set of subsections
that explains it (entry points, screens, rules, data, errors — only what's needed).
Present tense, short sentences. Reference code only when the reader needs it to
follow the point (an existing gate, a store pattern).

## Rejected ideas

Deliberately rejected ideas, one line each: **idea** — why rejected. This section
exists so nobody re-proposes them. If an idea was merely discussed and dropped
without a reason, it doesn't belong here.

## Open questions

items (accepted risks checked during device testing) live here too.
